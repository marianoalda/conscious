# World Format Version 3

## Status

Version 3 is the current world format. `world_serialize()` writes version 3, whichever version was loaded.

Version 3 stores the world age and, on each layer, the tick at which that layer was last simulated. The rest of the version 2 layout stays in place: world dimensions, modularity, and one dense heightmap with a clock.

The on-disk file still contains exactly one heightmap. The runtime keeps layers in an array so that later layers can be added in memory. That array is not written as a count or as a sequence of arbitrary layers. A new layer type on disk requires a new format version.

## Units

Two units are part of the format. The file has no unit fields.

| Quantity                                      | Unit         | Symbol |
| --------------------------------------------- | ------------ | ------ |
| Width, depth, cell size, heights              | millimetre   | mm     |
| World age and last simulation tick            | millisecond  | ms     |

One world tick is one millisecond.

```text
age = 1000
```

means the world is 1 second old.

All multi-byte integers are **big-endian**.

## File layout

```text
 0  magic                 4     CWLD
 4  version               4     3
 8  width                 4     uint32, mm
12  depth                 4     uint32, mm
16  modularity            8     CLOSED or MODULAR
24  age                   8     uint64, ms
32  layer marker          4     _LYR
36  layer type           16     TYPE_HEIGHTMAP
52  layer name           16     LYR_HEIGHTMAP
68  clock                 8     CLK_NOEV or CLK_dddd
76  last simulation tick  8     uint64, ms
84  storage               4     ST_D
88  cell size             4     uint32, mm
92  minimum height        4     int32, mm
96  height values    variable   uint32 offsets
```

The fixed prefix occupies **96 bytes**. Height values start at offset 96.

```text
file size = 96 + (cell_width × cell_depth × 4)
```

## Header

| Offset | Size | Type     | Meaning      |
| -----: | ---: | -------- | ------------ |
|      0 |    4 | bytes    | Magic `CWLD` |
|      4 |    4 | `uint32` | Version `3`  |

```text
43 57 4C 44 00 00 00 03
```

`CWLD` is `43 57 4C 44`. The loader rejects any other magic before it reads the version. A known magic with a version other than 0, 1, 2, or 3 is an unsupported version, not a version 3 file.

## World dimensions

| Offset | Size | Type     | Meaning   |
| -----: | ---: | -------- | --------- |
|      8 |    4 | `uint32` | Width, mm |
|     12 |    4 | `uint32` | Depth, mm |

Both must be greater than zero. They belong to the world, not to the layer.

```text
width  = 10000
depth  = 10000
```

is 10 m × 10 m.

## Modularity

Modularity is a property of the whole world. It is an 8-byte string, zero-padded on the right.

| Value     | Bytes                     | Meaning                          |
| --------- | ------------------------- | -------------------------------- |
| `CLOSED`  | `43 4C 4F 53 45 44 00 00` | The world is a closed rectangle  |
| `MODULAR` | `4D 4F 44 55 4C 41 52 00` | Opposite edges of the world meet |

Any other 8 bytes are invalid.

The current engine stores this property and prints it. It does not yet wrap coordinates when the value is `MODULAR`.

## World age

| Offset | Size | Type     | Meaning        |
| -----: | ---: | -------- | -------------- |
|     24 |    8 | `uint64` | World age, ms  |

The age is the world's absolute time. The simulation starts from this value and increments it by one millisecond after each completed step.

Version 0, 1, and 2 do not store an age. Loading them produces an age of `0`.

## Layer marker, type, and name

Version 3 defines exactly one layer, and it is a heightmap. There is no layer-count field.

| Offset | Size | Field  | Canonical contents                         |
| -----: | ---: | ------ | ------------------------------------------ |
|     32 |    4 | Marker | `_LYR` (`5F 4C 59 52`)                     |
|     36 |   16 | Type   | `TYPE_HEIGHTMAP` and two zero bytes        |
|     52 |   16 | Name   | `LYR_HEIGHTMAP` and three zero bytes       |

The marker must match all four bytes. The loader accepts the type and the name when their significant characters match; the writer always emits the zero-padded canonical form.

## Clock

The clock is 8 bytes. It decides whether the layer is simulated, and on which ticks.

| Encoding   | Bytes                    | Meaning                                              |
| ---------- | ------------------------ | ---------------------------------------------------- |
| `CLK_NOEV` | `43 4C 4B 5F 4E 4F 45 56` | Static. The layer is not simulated.                  |
| `CLK_dddd` | `43 4C 4B 5F` plus digits | Simulated every `2^dddd` milliseconds.               |

`dddd` is four decimal digits, `0000` through `9999`. Each digit is an ASCII byte from `30` to `39`.

```text
CLK_0000    every tick           period = 1 ms
CLK_0001    every second tick    period = 2 ms
CLK_0003    every 8th tick       period = 8 ms
CLK_NOEV    never
```

A tick `T` is one of the layer's ticks when `T` is a multiple of the period. With a period of `2^n` that is the test `T & ((1 << n) - 1) == 0`. Exponent `0` matches every tick, including tick `0`.

The format can store an exponent up to `9999`. The current simulator does not run a layer whose exponent is `64` or greater, because that period does not fit in the 64-bit tick.

`CLK_NOEV` is the clock written for a heightmap loaded from version 1, whose evolution field was `EV_N`.

## Last simulation tick

| Offset | Size | Type     | Meaning                         |
| -----: | ---: | -------- | ------------------------------- |
|     76 |    8 | `uint64` | Last tick on which this layer was simulated, ms |

The simulator writes this field when it actually runs the layer. A static layer keeps the value loaded from the file.

Version 1 and version 2 do not store this field. The loader sets it to `0`.

## Storage, cell size, and minimum height

| Offset | Size | Type     | Meaning              |
| -----: | ---: | -------- | -------------------- |
|     84 |    4 | bytes    | `ST_D`               |
|     88 |    4 | `uint32` | Cell size, mm        |
|     92 |    4 | `int32`  | Minimum height, mm   |

`ST_D` is `53 54 5F 44`. It means dense storage: one height value for every cell. Version 3 defines no sparse heightmap.

The cell size must be greater than zero, and both world dimensions must be exact multiples of it.

```text
cell_width = width / cell_size
cell_depth = depth / cell_size
cell_count = cell_width × cell_depth
```

The cell size belongs to the heightmap, not to the world. A later layer could use another resolution. Version 3 has only this layer, so the file contains one cell size.

The minimum height may be negative. A stored code of `0` is that elevation.

```text
min_height = -5000
```

is 5 m below the reference level.

## Height values

Each value is a big-endian `uint32`. It is an offset above `min_height`, not an absolute elevation.

```text
elevation = min_height + height_value
```

Both quantities are millimetres. For example:

```text
min_height   = 1000
height_value = 7
elevation    = 1007 mm
```

There is no count in the file. The loader reads `cell_count` values. They are ordered by row, and within each row from left to right, from the first row to the last.

The value block occupies `cell_count × 4` bytes.

## Validation

The loader rejects the file when any of the following is true:

* the magic is not `CWLD`;
* the version is not one of 0, 1, 2, or 3;
* any required field is truncated;
* width or depth is `0`;
* modularity is not `CLOSED` or `MODULAR` with the padding defined above;
* the layer marker is not `_LYR`;
* the layer type is not `TYPE_HEIGHTMAP`;
* the layer name is not `LYR_HEIGHTMAP`;
* the clock is not `CLK_NOEV` and not `CLK_` followed by four digits;
* the storage is not `ST_D`;
* the cell size is `0`;
* width or depth is not an exact multiple of the cell size;
* the height values are truncated.

The loader does not require the file to end at the last height value. Bytes after the defined content are not part of version 3.

## Worked example

The development ramp, `modules/data/world-v3-ramp.bin`, is 496 bytes.

| Field                  | Value                          |
| ---------------------- | ------------------------------ |
| Width                  | 10,000 mm                      |
| Depth                  | 10,000 mm                      |
| Modularity             | `CLOSED`                       |
| Age                    | 13,987 ms                      |
| Clock                  | `CLK_NOEV`                     |
| Last simulation tick   | 0 ms                           |
| Storage                | `ST_D`                         |
| Cell size              | 1,000 mm                       |
| Cells                  | 10 × 10                        |
| Minimum height         | 1,000 mm                       |

Every row stores the same offsets:

```text
1000 1001 1002 1003 1004 1005 1006 1007 1008 1009
```

The corresponding elevations are 2000 mm through 2009 mm. The first offset is at offset 96. The last occupies bytes 492–495.

```text
96 + 100 × 4 = 496 bytes
```

The beginning of that file is:

```text
Offset  0:  CWLD
Offset  4:  00 00 00 03
Offset  8:  00 00 27 10          10000 mm
Offset 12:  00 00 27 10          10000 mm
Offset 16:  CLOSED followed by two zero bytes
Offset 24:  00 00 00 00 00 00 36 A3    13987 ms
Offset 32:  _LYR
Offset 36:  TYPE_HEIGHTMAP and two zero bytes
Offset 52:  LYR_HEIGHTMAP and three zero bytes
Offset 68:  CLK_NOEV
Offset 76:  00 00 00 00 00 00 00 00    0 ms
Offset 84:  ST_D
Offset 88:  00 00 03 E8          1000 mm
Offset 92:  00 00 03 E8          1000 mm
Offset 96:  first stored offset 1000
```

## What the writer emits

`world_serialize()` writes the header (`CWLD` and version 3) and then the single heightmap found in the runtime layer array:

* world width, depth, modularity, and age;
* the heightmap clock and last simulation tick;
* `ST_D`, the cell size, the minimum height, and every stored offset.

If the world has no heightmap layer, serialization fails. Version 3 cannot represent a world without that layer, and it cannot represent a second layer.

Loading a version 0, 1, or 2 file and saving it produces a version 3 file. Missing time fields are written as `0`, except the age when the simulation has advanced it before the save.
