# World Format Version 4

## Status

Version 4 is the current world format. `world_serialize()` writes version 4,
whichever version was loaded.

Version 4 keeps the version 3 world header and dense field layers, and adds
**individual** layers: static species with one record per being (not one
value per cell). There is no autoevolution in the format.

Version 3 files remain loadable. Saving always writes version 4.

## Units

Same as version 3: millimetres, milliseconds, and W/m² for daylight.
All multi-byte integers are **big-endian**.

## File layout

```text
 0  magic                 4     CWLD
 4  version               4     4
 8  width                 4     uint32, mm
12  depth                 4     uint32, mm
16  modularity            8     CLOSED or MODULAR
24  age                   8     uint64, ms
    then zero or more layer blocks until EOF
```

Dense layers (`TYPE_HEIGHTMAP`, water, light, humidity, fertility, grass,
grass age) use the same block layout as [version 3](v3.md): storage
`ST_D` / `ST_8` / `ST16`, cell size, minimum, then cells.

## Individual layers

Any number of `TYPE_INDIVIDUAL` layers may appear. At most one layer per
**species** string. Layer name is always `LYR_INDIVIDUAL`.

```text
 0  layer marker          4     _LYR
 4  layer type           16     TYPE_INDIVIDUAL
20  layer name           16     LYR_INDIVIDUAL
36  clock                 8     CLK_NOEV or CLK_dddd
44  last simulation tick  8     uint64, ms
52  species              32     e.g. SPECIES_RABBIT_FUNCTIONAL
84  storage_depth        16     FUNCTIONAL or DEEP
100 species_version       4     uint32
104 individual_count      4     uint32
108 individuals…       variable
```

| Field | Meaning |
| ----- | ------- |
| species | Static species id. First: `SPECIES_RABBIT_FUNCTIONAL`. |
| storage_depth | `FUNCTIONAL` = pose (+ basic behaviour params in later species versions). `DEEP` = FUNCTIONAL plus mind; **not used yet** (loader rejects). |
| species_version | Format of the per-individual payload for that species. Shared numbering idea across species; missing newer fields get defaults when reading older versions. |
| individual_count | Number of individual records that follow. |

`SPECIES_RABBIT_FUNCTIONAL` uses depth `FUNCTIONAL` and species_version `1`.

### Individual record (rabbit functional, species_version 1)

```text
 0  marker                4     _IND
 4  id                    4     uint32 serial (nonzero)
 8  x_mm                  4     int32
12  y_mm                  4     int32
16  z_mm                  4     int32
20  orientation_mrad      4     int32
```

24 bytes per individual.

- Coordinates are world millimetres from the south-west corner; **Y** is north.
- **Z** is stored. For beings that walk on the surface it matches terrain
  elevation at `(x,y)` (see helpers below). Negative Z is allowed later
  (e.g. a rabbit in a burrow).
- **Orientation** is milliradians about the vertical axis: **0 = east (+X)**,
  positive = counter-clockwise (mathematical convention).

## Species payload evolution

Version 4 locks the **individual-layer frame** (species string, storage
depth, species_version, count, then records). Further changes to what
each species stores inside a record are owned by that species'
serialize/deserialize path (for example `world_species_rabbit.*`), not
by a new world-format version, unless the shared frame itself must
change.

## Provisional rabbit motion

The engine may move `SPECIES_RABBIT_FUNCTIONAL` individuals one metre
per calendar day along their orientation. That behaviour is
**provisional**: it exists only to check that a rabbit can be seen to
move through the world. It is not the real behaviour model for 0.2.

## Future helpers

Not required for load/save of v4; declared for later use:

1. **`world_individual_alloc_id(world, species)`** — return a new unused
   serial for that species layer (for example `max(existing ids) + 1`).
2. **`world_individual_surface_z_mm(world, x_mm, y_mm, &z_mm)`** — sample the
   heightmap at `(x,y)` and return elevation in millimetres for a being that
   walks on the surface.

## Compatibility

`world_load()` dispatches on the version field. Version 4 is accepted.
`world_serialize()` always writes version 4.
