# World Format Version 2

## Status

Version 2 adds two properties that version 1 cannot store:

* modularity of the whole world;
* a clock on the heightmap layer.

It does not store the world age or the layer's last simulation tick. Those appear in version 3.

`world_serialize()` does not write version 2. It writes version 3. Version 2 remains loadable.

## Units

Distances are millimetres. There is no unit field in the file.

Version 2 has no stored time tick. The layer clock's period is a power of two of the basic world tick. From version 3 onward, that tick is one millisecond.

All multi-byte integers are **big-endian**.

## File layout

```text
Offset
0        8        16       24       28       44       60       68       72       76       80
┌────────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┐
│ header │ width  │ depth  │ modular│ _LYR   │ type   │ name   │ clock  │ ST_D   │ cell   │ ...
│ 8      │ 4      │ 4      │ 8      │ 4      │ 16     │ 16     │ 8      │ 4      │ 4+4    │ values
└────────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┘
```

The fixed prefix, through `min_height`, occupies **80 bytes**. Height values start at offset 80.

```text
file size = 80 + (cell_width × cell_depth × 4)
```

## Header

| Offset | Size | Type     | Meaning        |
| -----: | ---: | -------- | -------------- |
|      0 |    4 | bytes    | Magic `CWLD`   |
|      4 |    4 | `uint32` | Version `2`    |

```text
43 57 4C 44 00 00 00 02
```

## World dimensions

| Offset | Size | Type     | Meaning     |
| -----: | ---: | -------- | ----------- |
|      8 |    4 | `uint32` | Width, mm   |
|     12 |    4 | `uint32` | Depth, mm   |

Both must be greater than zero.

```text
width  = 10000
depth  = 10000
```

is a world of 10 m × 10 m.

## Modularity

Modularity is a property of the world, not of a layer. It is an 8-byte string, zero-padded on the right.

| Value     | Bytes                          | Meaning                                      |
| --------- | ------------------------------ | -------------------------------------------- |
| `CLOSED`  | `43 4C 4F 53 45 44 00 00`      | The world is a closed rectangle              |
| `MODULAR` | `4D 4F 44 55 4C 41 52 00`      | Opposite edges of the world meet             |

Any other content is invalid.

The current engine stores this property. It does not yet use it to wrap coordinates.

## Layer

Version 2 contains exactly one layer, and that layer is a dense heightmap. There is no layer count in the file.

| Offset | Size | Field            | Representation                          |
| -----: | ---: | ---------------- | --------------------------------------- |
|     24 |    4 | Marker           | `_LYR` (`5F 4C 59 52`)                  |
|     28 |   16 | Type             | `TYPE_HEIGHTMAP`, zero-padded           |
|     44 |   16 | Name             | `LYR_HEIGHTMAP`, zero-padded            |
|     60 |    8 | Clock            | `CLK_NOEV` or `CLK_` plus four digits   |
|     68 |    4 | Storage          | `ST_D` (`53 54 5F 44`)                  |
|     72 |    4 | Cell size        | `uint32`, millimetres                   |
|     76 |    4 | Minimum height   | `int32`, millimetres                    |
|     80 |  var | Height values    | `uint32` offsets, one per cell          |

Version 1's `EV_N` field is gone. The clock replaces that role. It is not the same bytes reinterpreted.

The loader matches the type and the name by their significant characters. The writer zero-pads both fields to 16 bytes. The marker, the clock, and `ST_D` are compared in full.

## Clock

The clock says how often the layer is simulated, as a power of two of the basic world tick.

| Encoding   | Meaning                                                      |
| ---------- | ------------------------------------------------------------ |
| `CLK_NOEV` | The layer is static. It is not simulated.                    |
| `CLK_dddd` | The layer is simulated every `2^dddd` world ticks.           |

`dddd` is four decimal digits, from `0000` to `9999`.

```text
CLK_0000    every tick          (2^0 = 1)
CLK_0003    every 8 ticks       (2^3 = 8)
CLK_NOEV    never
```

`CLK_NOEV` is the eight bytes `43 4C 4B 5F 4E 4F 45 56`. A divisor uses `CLK_` (`43 4C 4B 5F`) followed by the four digit bytes.

An exponent greater than `9999` cannot be stored. The current simulator also skips a layer whose exponent does not fit in a 64-bit tick, that is, an exponent of 64 or more.

Version 2 does not store the tick on which the layer was last simulated. The loader sets that runtime field to `0`.

## Cell size and minimum height

The cell size is a `uint32` in millimetres and must be greater than zero. Width and depth must both be exact multiples of the cell size.

```text
cell_width = width / cell_size
cell_depth = depth / cell_size
cell_count = cell_width × cell_depth
```

The minimum height is an `int32` in millimetres. A stored height of `0` means that elevation.

```text
elevation = min_height + height_value
```

Both terms are millimetres. For example, `min_height = 1000` and `height_value = 7` is an elevation of 1007 mm.

## Height values

Each value is a big-endian `uint32`. The heightmap is dense: one value per cell, with no count field. The count is derived from the dimensions and the cell size.

Values are stored row by row. Inside a row they run from left to right. Rows run from the first to the last.

The data size is `cell_count × 4` bytes.

## Validation

The loader rejects the file when any of the following is true:

* the magic is not `CWLD`;
* the version is not `2`;
* a multi-byte field is truncated;
* width or depth is `0`;
* modularity is neither `CLOSED` nor `MODULAR`, with the padding required above;
* the layer marker is not `_LYR`;
* the layer type is not `TYPE_HEIGHTMAP`;
* the layer name is not `LYR_HEIGHTMAP`;
* the clock is neither `CLK_NOEV` nor `CLK_` followed by four digits;
* the storage is not `ST_D`;
* the cell size is `0`;
* width or depth is not an exact multiple of the cell size;
* the heightmap values are truncated.

## Loading into the current runtime

| Runtime field            | Source                                      |
| ------------------------ | ------------------------------------------- |
| Modularity               | The modularity field                        |
| World age                | `0` (not stored in version 2)               |
| Heightmap clock          | The clock field                             |
| Last simulation tick     | `0` (not stored in version 2)               |
| Cell size, minimum, grid | The heightmap fields                        |

Saving that world afterwards writes version 3, including the age and the last simulation tick.

80 + 100 × 4 = 480 bytes
