# World Format Version 0

## Status

Initial world format.

This version defines the minimum binary structure required to identify a Conscious world file and its format version.

## Binary layout

A version 0 world file consists of exactly 8 bytes:

| Offset |    Size | Field   | Description                                   |
| -----: | ------: | ------- | --------------------------------------------- |
|    `0` | 4 bytes | Magic   | Identifies the file as a Conscious world file |
|    `4` | 4 bytes | Version | Format version number                         |

```text
Offset
0                   4                   8
┌───────────────────┬───────────────────┐
│       Magic       │      Version      │
│      4 bytes      │      4 bytes      │
└───────────────────┴───────────────────┘
```

## Magic

The magic value is a fixed 4-byte identifier placed at the beginning of the file.

The current identifier is:

```text
CWLD
```

Its byte representation is:

```text
43 57 4C 44
```

The magic allows the loader to distinguish a Conscious world file from an unrelated file before interpreting the remainder of the header.

## Version

The version field is an unsigned 32-bit integer.

Version 0 is represented as:

```text
00 00 00 00
```

The field uses **big-endian byte order**.

Therefore, the complete version 0 file is:

```text
43 57 4C 44 00 00 00 00
```

## File size

A version 0 world file is exactly:

```text
8 bytes
```

No additional data is defined by version 0.

## Loading

A version 0 file is recognized when:

1. The first four bytes contain the `CWLD` magic.
2. The following four bytes contain the value `0`.

The loader must reject files with an invalid magic value.

A file containing a recognized magic value but an unsupported version must be reported as an unsupported world format rather than being interpreted as version 0.

## Serialization

Version 0 contains no world state beyond the format identification header.

`world_serialize()` therefore writes the 8-byte version 0 header when version 0 is the current serialization format.

## Future compatibility

Version 0 is retained as a historical format once a later format version is introduced.

Its deserialization implementation must remain available so that existing version 0 world files can continue to be loaded.

Future versions may append or redefine world data, but they must use a distinct format version number and have their own specification.
